## 2. 标准工作流

1. **搭场景** — 拖卡片或用示例场景；`Ctrl+D` 复制、`Del` 删除、双击列表项重命名、箭头键微调（`Shift` 改高度）。
2. **定机位** — 把视口调到想要的构图，按 `C`（新建机位：以当前视角建机位）；或在「运镜」里改焦段/画幅/机身。
3. **选运镜** — 挑一条预设（自动铺 9 个关键帧），再拖节点微调；`K` 在当前时间补一帧。
4. **排动作** — 选人物 → 选动作（16 种）→ 在时间轴上换时间、挪位置、`K` 记录走位关键帧；勾选「朝向前进方向」后人物会自动沿路径转身，落脚相位按步幅同步（走路/奔跑不会滑步）。
5. **调氛围** — 选预设再手动微调；快速迭代时按 `L` 关掉光影。
6. **导出** — 选分辨率/帧率 → 开始录制（1 秒视频≈1 秒等待）；按实际服务能力交付提示词与参考素材；运镜 JSON / 深度用于本地检查或专门支持的管线，不保证通用模型接收。

## 7. 怎么看「现在预览的是哪台机位」

同一个身份（编号 + 名字 + 颜色）会同时出现在四个地方，扫一眼就知道画面来自哪台机器：

| 位置 | 内容 |
| --- | --- |
| 预览画面左上角角标（仅预览时出现） | `2/3 · B · 环绕建筑` ＋ `环绕 Orbit ｜ 24mm ｜ 9 关键帧 ｜ 1.85:1学院比例`，前面一块该机的颜色 |
| 底部左侧 HUD（编辑时也常驻） | 当前机位名、运镜、焦段、关键帧数、画幅、时长/帧率 |
| 视口里每台机位头顶的 3D 名牌 | `1 · A · 推镜跟随` ＋ `推镜 Dolly In ｜ 35mm`；活动那台额外标 `● 预览中`（未预览时是 `○ 当前机位`）并加粗边框，随 `H` 显隐，**导出时自动隐藏，不会烧进视频** |
| 左栏「机位」列表 / 运镜页机位 chips / 时间轴关键帧小球 | 行首圆点、行左边框、chips 左边框、路径线、关键帧小球全部用同一颜色 |

配色规则：活动机位永远是琥珀 `#ffb547`，其余按 `#7fd6ff #8ee6b0 #c9a3ff #ffb0a3 #a9d6ff #ffe08a #9be6d0 #e0a3ff` 轮换；名牌还会按观察距离自动缩放，远景也读得清。

切换预览机位的四种方式：左栏点行、运镜页 chips、`[` `]` 直接上一台/下一台（弹 toast 报名字）、或在视口点镜头本体。相关 API：`App.cycleShot(dir)`、`App.refreshShotColors()`、`Shot.colorHex` / `Shot.refreshColors()`。

## 8. 预览与导出为什么一致

- 关键帧保存的是**水平视场角**（`f` 字段），不是 three 的垂直 fov；这样切画幅时构图不会漂。
- 预览画布通常是任意形状：`Stage.framingAspect()` 会按「取景框在画布中的占比」把 hfov 换算成垂直 fov，所以**框内画面 = 导出画面**，框外多出来的是安全区。
- 导出时先按输出分辨率 `setSize`，再用 `scissor + viewport` 把画面渲染到输出画布中央的取景框矩形，其余填黑 —— 视频里的黑边和预览一致（选 1920×804 这类与画幅同比例的分辨率就没有黑边）。

## 12. 运镜流畅度：为什么关键帧处不再「顿一下」

旧实现有三处会制造停顿感，都已经改掉（`src/mover.js`）：

| 根因 | 现在的做法 |
| --- | --- |
| 每个关键帧两侧各自套一次缓动 → 过节点速度必然归零 | 缓动只作用于**整段**（`scope:'global'`），段内线性；需要逐帧强调时把作用域切回「逐段」 |
| 均匀参数化（按节点序号取点）→ 直段快、弯段慢 | 弧长参数化 `_paraT`：按每段实际长度分配时间，同时仍保证**关键帧精确落在自己的时间上** |
| 对 Euler 关键帧做球面插值 → pan+tilt 同时动时抖 | 前方/上方两个向量样条（C1 连续），只在少于 3 帧时退回 `slerp` |
| FOV 打点会来回摆 | 单调三次（Fritsch–Carlson）插值，焦段只按关键帧顺序单调变化 |

右栏 **运镜 → 流畅度 / 曲线** 提供开关与自测：

- **缓动作用域 / 缓动曲线 / 匀速（弧长）/ 路径张力 / 朝向插值**，改完立即生效，可「同步到全部机位」。
- **平滑体检**：给出相对速度 min–max 与「关键帧处掉速 %」（帧处速度相对左右半格基线的跌幅）。`掉速 0%` = 完全没有停顿感；旧版逐段 `inOut` 是 **90%**。
- **按弧长重排时间（真匀速）**：关键帧位置不动，把每帧时间改成按弧长比例 —— 路径本身长短不匀时（例如 `reveal`、手绘长路径）一键变成全程匀速。

实测（`node test/motion.mjs`，示例场景三个机位）：

```
A · 推镜跟随   速度 1.000× – 1.000×   关键帧处掉速 0%
B · 环绕建筑   速度 0.998× – 1.001×   关键帧处掉速 0%
C · 升镜揭示   速度 0.341× – 1.751×（路径每段长短不匀）→ 按弧长重排时间后 0.999× – 1.005×
把「缓动作用域」切回旧的逐段模式：C 的关键帧处掉速立刻变成 90% —— 这就是当初「到点就停」的来源。
```

> 常量路径速度 ≠ 常量角速度：环绕 / 摇镜经过近处物体时画面转速本来就会变，这是物理，不是卡顿。

## 13. 手动改关键帧曲线（`V`）

时间轴上方是曲线抽屉，三个通道：

| 通道 | 含义 | 用在哪 |
| --- | --- | --- |
| **进度** | 时间重映射（纵轴＝归一化进度，单调钳制，空＝匀速） | 起手慢 / 中段冲 / 收尾稳，或做「慢-快-慢」强调 |
| **视场** | 在关键帧上叠加水平视角曲线 | dolly zoom、变焦推近 |
| **抖动** | 0–1 倍率乘到手持幅度 | 开场稳、越跑越喘 |

操作：**拖点**改值 · **Alt+拖**拉贝塞尔手柄 · **双击**切模式（平滑 / 线性 / 阶梯） · **右键**删点 · **空白处单击**加控制点 · 底部速度条直接告诉你哪里在减速 · 播放头跟着时间走。
预设：线性、缓入缓出、缓入、缓出、鞭甩、慢-快-慢、漂移（跟拍最自然：两端略慢、中段均匀）。

曲线与机位/物体绑定：选中机位编辑器位曲线，选中带走位的物体则编物体路径曲线；两者都随 `toJSON` 落进工程 JSON，并在「导出运镜数据 JSON」里以 `curves.progress / curves.shake` 输出（含 `motion` 质量参数与 `key_jump`）。

## 14. 地形编辑（`T`）

`src/terrain.js`：`n×n` 高度场（33 / 65 / 97 / 129，可调尺寸 60–400 m）。

- **笔刷**：抬起 · 压低 · 平滑 · 抹平 · 噪声 · 高原台地；按住左键拖动连续绘制，**Shift 反向**（例如按住 Shift 抬＝压）；半径 2–40 m、力度 0.05–2；「整体平滑」削掉笔刷尖刺。
- **一键生成**：平原 · 丘陵 · 山脊 · 海岛 · 弹坑群 · 峡谷 · 台地；起伏幅度 0.5–24 m。
- **地貌配色**：草地 / 针叶林 / 沙漠 / 岩地 / 雪原 / 异星 / 焦土（顶点色随高度与坡度混合出岩与雪线）。
- **水面**：独立平面 + 水位（海岛生成会自动落到合适水位）。
- **贴地**：拖放模型、拖动、`方向键`微调都会跟随 `heightAt`；把物体抬高 **>1.6 m** 视为刻意悬空，自动脱离贴地（浮空仙岛、飞舟就靠这个）。「地形」页里有「选中物体：贴地 / 离地 1.5 m」的强制切换与实时高度读数。
- **保存**：高度以 Int16(厘米) → base64 存进工程 JSON（整份约 48 KB），加载后逐位还原；开启地形时默认地面与网格自动让位，避免穿插。
- 脚本可用：`app.terrain.heightAt/slopeAt/normalAt/snap/paintAt/generate/smoothAll/setBiome/setWaterLevel`。

## 16. 空白场景 / 删除机位 / 一键清空（+ 撤销）

这三件事都是「搭景」时最高频的动作，所以入口放在最显眼的位置，且全部可撤销：

| 操作 | 入口 | 行为 |
| --- | --- | --- |
| **空白场景** | 顶栏「◫ 示例场景」→ 第一排 `＋ 空白场景` | 清掉模型与机位，**保留地面、开启压平的地形与当前光影**，直接从零摆景 |

## 18. 已知边界

- 录屏是**实时**录制，帧率受 GPU 影响；高分辨率/高帧率建议先按 `L` 关光影。
- 音频不导出（MediaRecorder 只取 `captureStream` 的视频轨道）。
- 工程 JSON 不含外部模型网格（只留位置与走位）；导入模型如带贴图需与 `.mtl` 同批拖入。
- 程序化动作为「节奏参考」级别，不做表演级细节（面部、手指）。
- 变形宽幅（2× anamorphic）按水平视角折算，不模拟椭圆焦外与炫光。
- 地形是高度场（每列一个高度），做不了倒挂悬崖与洞窟 —— 需要时用「断崖 / 乱石堆 / 天生石门」模型补。
- 「进度」曲线是整段的时间重映射：加了明显缓入缓出后，摄像机**经过**某关键帧的时刻会偏离它在时间轴上的标记位置（这是曲线定义如此）；要让两者严格一致就用「按弧长重排时间」或把曲线清空。
- 曲线抽屉不编辑物体旋转/缩放通道（朝向沿路径自动解决，缩放走物体参数）。

## 19. 视觉回归：闪烁 / 抖动 / 对焦 / 贴地（`test/aim.mjs`）

观感类问题不能靠肉眼「看起来好了」，所以有一条可重复的量化门禁：

```bash
node test/aim.mjs                     # 22 套模板 × 每个机位，逐帧量（约 7 分钟）
ONLY=cn-garden,space-undock node test/aim.mjs   # 只跑指定模板（调试用，约 1 分钟/套）
```

每个机位先推 6 帧预热，再在 u=0.18 / 0.48 / 0.78 取三个窗口 × 12 帧，**严格按 1/30 s 间距**采样（间距错了 `resid` 会虚高 8 倍，别拿不同间距的数横比）：

| 指标 | 含义 | 门禁 |
| --- | --- | --- |
| `resid` | 相邻帧角度差的残差（有没有高频「颠」） | ≤0.16（whip / fpv 这类故意甩的镜头只查 `rotJitMax ≤3`） |
| `aim.resid` / `off` | 主体是否锁在画面中央（偏构图） | 偏移 ≤0.34（松散运镜 1.05） |
| `occl` | 机位到主体之间有没有被别的模型挡住（列出挡住的东西） | 0 |
| `belowGround` / `underWater` | 相机穿地 / 泡在水里 | ≤0.2 |
| 物体 `悬空/埋地/泡水` | 物件**包围盒底面** vs 脚下那一片地面的高差范围（坡地上不误判），角色走位路线整条扫水 | 全部 0 |
| `flickStructMax` | 钉住相机、**隐藏人物与特效**后两次渲染的差异像素比（共面 / 阴影重采样这类真的不该变的东西） | ≤0.8% |
| `flickLumMin` | 读回画面的平均亮度（防止「黑屏所以不闪」） | ≥2 |

`flickMax`（不隐藏任何东西的全量差异）会包含人群漫游这类**本该动**的变化，所以只看不卡；卡的是 `flickStructMax`。脚本还会把任何 `运镜「id」不认识的参数被忽略` 警告（`IGNORED-PARAM`）当失败 —— 模板写了不存在的参数会静默失效，之前 5 个 fpv 机位就是这么坏掉的。结果写在 `test/aim-result.json`。

## 20. 人群随机漫游

「人群」资产（`char:crowd`）里的每个人现在会自己找地方走，不再原地踏步：

- 每个角色在自己的**漫游范围**内挑一个地面点走过去，走到就歇 0.8–3.4 s（按「停下聊天概率」决定是站着还是转身跟身边 2 m 内的人 `talk`），然后换下一个点；
- 朝向用指数平滑转动（不会瞬间扭头），步伐相位按**各自实际位移**推进，所以不滑步；
- 逐个角色贴地（坡地上不会半截埋进土里），选点时**避开水深超过水面 5 cm 的地方**；如果整圈都是水（比如池子里），退一步放宽到 35 cm 再挑，挑不到就原地挪一小步 —— 不会集体卡死；
- 漫游范围跟着物件走：拖动 / 旋转整个人群，角色就在新的位置附近绕，不会留在原地。

参数（右侧「物体」面板，随工程 JSON 与提示词一起导出）：`随机漫游`（默认开，老的工程 JSON 里没这个字段也按开处理）、`漫游速度 m/s`、`漫游范围半径 m`、`走累了停下聊天概率`。动作选 `sit / sitground / lie` 时不漫游（免得人被拖着走）。要一群人整队行进 / 走位打点，仍然用「运镜 / 走位」关键帧路径 —— 那是精确轨迹，随机漫游是环境人群。

### 楼梯一放，楼板上就出现洞口（通向上一层）

这是本项需求的重点，做法是**真几何**而不是贴图：

1. 每个楼梯生成时会导出一个「洞口需求」`root.userData.stairOpen = { w, d, cx, cz, y, band }`（单跑取梯顶 + 平台那一段、双跑取上跑梯顶、螺旋给一个圆；`洞口长度` 控制留多长，填 `0` 就是整段梯都留空）。
2. `App.updateCeilingHoles()` 把每个洞口四角从**楼梯局部坐标**变换到**天花板局部坐标**，写进天花板的 `params.holes`，天花板生成器再用 `THREE.Shape` + `Path`  holes + `ExtrudeGeometry` 把板子挖穿（`slabWithHoles()`）。
3. 匹配规则是**竖向高度带**：只挖「板面高度 ≈ 楼梯顶面高度（差在 `band` 内）」的那一块楼板 —— 所以是「通向上一层」而不是把每一层都戳穿。
4. 触发时机：放样 / 拖动结束 / 改参数（楼梯或天花板）/ 载入模板 / 重贴地面。楼梯**挪开洞就跟过去、删掉洞就自己补回**；单独关掉某块板子的开孔把它面板里的 `让楼梯在此留洞` 关掉即可。
5. 洞口多边形存在 `params.holes` 里，**随工程 JSON 一起导出**，换台机器打开、或用 AI 提示词复现时洞口位置一模一样。

放样建议：把地形关掉（或先压平），层高按 `3.4 m` 走 —— 天花板 / 屋顶这两类构件带 `elev` 默认值，落点自动抬到一层之上（`3.2 / 3.4 m`），不会被贴地拽回地面。一键搭好直接看效果：顶栏「◫ 示例场景」→ **构件 · 两层小楼（楼梯穿楼板）**。

- 模板里的运镜参数都过了一遍「未知参数」闸门：`node scripts/strip-dead-move-params.mjs` 会把 `p: { … }` 里那个预设**不认的键**删掉（曾经有 40 个：`follow` 的 `dist/elev`、`dollyZoom` 的 `zoomIn`、`orbitPush` 的 `height/radius/pull`… 它们只会被忽略，留着会让用户以为调了有用）。
  `test/aim.mjs` / `test/parts.mjs` / `test/house.mjs` 都把 `不认识的参数被忽略` 计入失败项，所以任何模板再写进一个无效键都会立刻红；`node test/_audit.mjs` 是专门跑这条的快查（22 套逐场景载入，只打印越界键）。
- 验证：`node test/parts.mjs`（16 项）与 `node test/house.mjs`（9 项）—— 里面用**射线**实测：门洞处水平射线一路穿过 8 m、墙垛处立刻命中；洞心向下的射线穿过楼板、旁边 1.6 m 处命中板面；楼梯平移 3.5 m 洞口中心同步平移 3.5 m；删楼梯后射线立刻命中（说明洞补回了）。截图 `test/31b-ceiling-hole.png`、`test/41-house-cutaway.png`。

## 22. 撤销 = 一步一个操作（`Ctrl+Z` / `Ctrl+Shift+Z`）

原来只在「删除机位 / 一键清空」前留快照，于是 `Ctrl+Z` 会把当前摆的景一次全退回 —— 这是缺陷。现在语义改成**一个操作 = 一步**：

| 操作 | 快照时机 | 合并规则 |
| --- | --- | --- |
| 放模型 / 删物体 / 加机位 / 删机位 / 复制 | 操作前 `beginOp()` | 不合并（一次一步） |
| 拖 W/E/R 手柄 | `transform-start` 时（按当前 `gizmoMode` 记标签） | 同一次拖拽只留一步 |
| 右侧改参数（滑块 / 数字框 / 开关 / 颜色） | 第一次改动时 | 同一物体的同一参数、1.4 s 内连续改动合并为一步（拖滑块不会撑爆栈） |
| 地形笔刷 | 每次**落笔**（pointerdown） | 一笔一步，抬笔再落笔是新的一步 |
| 加 / 清 物体关键帧 | 操作前 | 不合并 |
| 载入模板 / 一键清空 / 打开工程文件 | 整份操作只留**一步** | `batchOp()` 期间挂起逐项快照（`_suspendUndo`） |

- 上限 40 步 / 12 MB（谁先到算谁），超出就从栈底丢；快照就是完整工程 JSON（含地形高度、机位关键帧、楼板 `holes`），所以撤销回来的场景和当时逐字节一致。
- **重做**：顶栏「↷」（撤销按钮旁）· `Ctrl+Shift+Z` · `Ctrl+Y`，独立 40 深；任何新操作会清掉重做栈。按钮在没有可撤销 / 可重做时变灰，`title` 里写着当前栈深（例如 `撤销（3 步可退）`）。
- 验证：`node test/parts.mjs` 里连着放 3 个构件 → 一次 `Ctrl+Z` 只剩 2 个（不是 0 个）、再来一次剩 1 个、`redo()` 回到 2 个；改参数撤销后回到原值。

## 23. 模型精度与外观完整度（顶栏「精度·」/ 光影面板）

模型是程序化的，所以「精度」不是导入设置而是**生成参数**：段数、倒角、表面贴图都由一个总开关统一控制。

### 三档精度

顶栏 `精度·均衡` 下拉（或 右侧「光影」→ 手动调光 → `模型精度`）：

| 档位 | 圆柱 / 球 / 锥段数 | 倒角 | 贴面细分 | 表面贴图 | 整场景三角面（`cn-palace` 34 件实测） |
| --- | --- | --- | --- | --- | --- |
| 省内存 lite | ×0.62 | 无 | ≤6 | 无（纯色） | 96,384 |
| 均衡 std（默认） | ×1.0 | 1× | ≤12 | 256² | 164,516 |
| 高细节 fine | ×1.85 | 1.8× | ≤24 | 512² | 466,714 |

- 默认仍是 **均衡**：低内存机器 / 长批量导出不受这次改动影响，`fine` 要用户主动选（选完会写进工程 JSON，下次打开自动是那一档）。
- 段数只在「本来就打算画圆」的地方加密：`< 8` 段的图元（四棱攒尖、方柱、楔形）保持棱角，不会被打磨成圆球。
- 切换档位 = 用当前参数重建全部模型：`cn-palace`（34 件）实测 `std` 564 ms、`fine` 1,624 ms；这算「看的效果」而不是「场景内容」，所以不占撤销栈的一步。

### 外观：程序化材质贴图（没有一张外部图片）

`src/detail.js` 在 canvas 上**逐像素算高度场**再转成 法线 / 粗糙度 / 近白反照 三张贴图：抹灰、混凝土骨料、砖、石砌、木纹、**瓦垄**、金属拉丝、玻璃雨痕、沥青、布料、皮革、皮肤毛孔、泥土。

- **显存有界**：一种材质全场景共用**一张** GPU 纹理，全局上限 15 种（抹灰 / 混凝土 / 砖 / 石砌 / 木 / 瓦 / 金属 / 玻璃 / 沥青 / 布 / 皮革 / 皮肤 / 泥土…）：`std` 每约 0.75 MB、`fine` 每约 3 MB，全用满也只有 11 MB / 45 MB，**不随模型数量增长**（`cn-palace` 实测 8 种 = 6.3 MB，`fine` 档 25 MB）。平铺密度不是靠 `texture.repeat` 复制纹理，而是**把物理尺寸烘进顶点 UV**（`fitUV()`）—— 一面 8 m 的墙和一堵 0.6 m 的矮墙吃到同一张贴图，但瓦缝 / 砖缝的真实大小都对。
- 已经带自己贴图的材质（立面窗格 canvas 贴图）**不被覆盖**，只补环境反射强度。
- 「光影」面板里 `表面贴图` 复选框可以整体关掉（回到纯色），内存优先模式（`L`）会自动关掉它并撤掉环境贴图。

### 环境反射：把天穹烘成 128×64 的小图

`Stage.setEnv()` 用 `PMREMGenerator` 把一张**程序化天穹**（渐变天空 + 太阳 + 地面反弹）转成环境贴图，金属 / 玻璃 / 水面立刻有高光和环境色，水面还能映出天光；颜色跟着**氛围预设**走（白天 / 黄昏 / 夜景的反射不一样，预设里的 `envInt` 现在真的被用上了），`环境反射强度` 滑块可手动覆盖，换预设即恢复该预设的建议值。仍然是零外部 HDR、单文件可离线打开。

顺带修掉一个响应性缺陷：`scene.environment` 在「有 ↔ 无」之间切换会让**全场材质重新编译**，之前每换一次氛围预设 / 每载入一套模板都要 3–6 s（`test/scenes.mjs` 里 `cn-garden` 6814 ms、`int-bedroom` 4606 ms）。现在改成「先把新 PMREM 建好 → 换引用 → 再释放旧的」，并把 140 ms 内的连续改色合并成一次重建：同一批模板降到 `cn-garden` 858 ms、`int-bedroom` 149 ms，22 套全部 < 1.8 s（这条本身就是 `test/scenes.mjs` 的 <3s/套 闸门）。

### 外观完整度：把「看着像」的小件补上

- **人物**（`character.js`）：手掌 + 四指 + 拇指、眼白 / 瞳孔 / 眉 / 鼻 / 耳 / 下颌 / 颈、袖口、领口、腰带、鞋头与鞋底；四肢胶囊段数随精度档走。人群（最多 40 人）只在 `高细节` 下加这些小件，`省内存` 下连单体人物也自动收掉 —— 否则一次多出 800 个 draw call。
- **建筑构件**（`bld.js`）：墙上的窗洞不再是空气洞 —— 补**洞口内壁（能读出墙厚）**、窗台板外挑、门洞门槛石、墙基 / 勒脚（`直墙` 面板新增 `墙基 / 勒脚`、`窗洞装玻璃` 两个开关）、压顶与圆扶手改成带倒角的截面；推拉窗加上下冒头与执手；楼梯每级踏步加**鼻线**与防滑条。
- **中式屋顶**：`curvedRoof()` 的举折曲线密度按精度档加密，屋面材质改走 `roofSurf()`（挂 `tile` 瓦垄浮雕，瓦垄沿排水方向起垄），15 处古建屋面 + `双坡 / 四坡` 屋顶全部受益。

## 24. 中式古建：把「缺的结构」补齐（牌楼 / 殿宇 / 塔 / 门楼 / 城墙 / 廊 / 桥 / 鼓楼）

起因是一张照片对照：真实牌楼下，我们的 `牌楼牌坊` 只有中间一间有屋顶、两侧是几根光柱子挂一块黑板 ——「结构都不完整，很多的中式古建都是缺少结构」。这一节写清了补了什么、以及怎么验。

同一轮截图对照还揪出另外两个只有「正立面」才看得出来的缺陷（构件清单查不出来）：

3. **彩画全都堆在明间**：`caihua(len, mats, o)` 从来不接受 `x`，所以每间梁枋上的彩画都被摆到构件组的中心 —— 从正面看就是「中间一道彩画 + 洞口里飘着两根」。现在 `caihua()` 支持 `x`，牌楼五间、回廊每段的彩画各自跟着本间的梁走（实测彩画 x = −7.93 / −4.67 / 0 / 4.67 / 7.93，与五个楼位一一对应）。
4. **正脊悬空**：`curvedRoof` 的屋脊实际高度是 `0.76h`（举折曲线到顶），而 `roofTrim` 把正脊按 `y0 + h` 摆 —— 每条脊都浮在屋面上方约 0.24 倍屋顶高，牌楼上是肉眼可见的一条黑影。改成 `y0 + h * 0.76` 之后所有中式屋顶（殿宇 / 门楼 / 鼓楼 / 亭 / 塔）的脊与脊兽一起落到屋面上（牌楼总高 10.94 → 10.71 m）。

顺带修掉两个真实缺陷：

1. **楼位算错**：旧版按 `bays` 推柱位时多塞了两个「出头」坐标，3 间牌楼的三个楼位只盖到左侧三个间隔（中间与右两间没楼）—— 这就是截图里「只有中间有屋顶」的原因。现在柱位 = 主柱 `bays+1` 根 + 出头柱 2 根，楼位逐间生成，实测 5 个楼位。
2. **匾额是一块黑板**：旧版用 `M.paint(0x1d2a24)`（近黑绿）当匾额，白天没有自发光时就是一块死黑矩形。现在匾额是真实蓝底 + canvas 金字 + 鎏金边框，`省内存` 档也不会变黑（不再依赖发光通道）。

### 补齐结构之后：合并、缓存与「切模板不卡」

结构补齐意味着一件牌楼就有几百个方盒 / 圆柱，所以这一轮同时做了三件事（都在 `src/geo.js`）：

- `mergeSimilar()`：把「同几何 + 同材质」的重复件压成一个 `InstancedMesh`（实例矩阵直接烘世界变换）。顺带修了一个更普遍的问题：`applyDetail()` 给材质挂上程序化贴图后材质就有了 `map`，任何「按材质合并」的逻辑都会跳过它 —— 现在按**贴图 uuid**判断是不是同一张图，带贴图的构件照样能合。门槛从「3 件起合」降到 **2 件**，因为实例化比复制顶点便宜得多。
- `bakeMerge()`：剩下的零碎件（尺寸各异、没法实例化）按**材质长相**分桶，顶点变换到构件组坐标后烘进一个 `BufferGeometry`。按「长相」而不是 `material.uuid` 分桶很关键：构建器每次 `M.paint()` 都新建材质，按 uuid 分桶等于什么都没合。UV 本来就是米制，拼起来贴图密度不变；被烘掉的来源件会留一份档案（`geo.userData.bakedMeta`），检查脚本仍能手把手数构件。
- **同一次 build 内的几何缓存**（`geoCacheBegin/End`，`buildAsset` 里开合）：同规格方盒 / 圆柱共用一份几何，跨物体不共用。再加一条：小于 16 cm 的构件不生成倒角盒（看不出来，但 `ExtrudeGeometry` 的代价要付）。同一件宫殿大殿的构建耗时 **226 ms → 37 ms**。

结果（中式古建 15 件全建一遍，浏览器实测）：`std` 档 **7,959 → 990** 次绘制（−87%），三角面 379,060；`lite` 791 / 197,392，`fine` 1,028 / 598,738，三档 NaN 均为 0。六件「构件总览」场景的绘制从 1,222 降到 686（`test/cnshot.mjs` 每次出图都会打印这行）。切模板：`cn-palace`（34 件）2,758 ms、`cn-snow-edict` 1,568 → **974 ms**（`node test/perf.mjs` 逐套量，22 套最贵的一套就是这座殿；该场景合并后世界节点 3,618 个、其中网格 2,143）。

这一轮合并自身踩到两个坑，都记在这里，因为它们都属于「清单全绿但画面破了」那一类：

1. **`mergeSimilar` 不该 dispose 来源几何**：加了 build 内几何缓存之后，「重复几何」其实是别处还在用的同一份 —— 一 dispose，别人的顶点就变成 0（牌楼只剩半边的屋面）。现在只摘节点、不动几何。
2. **烘顶点时位置与法线不能共用一个写入下标**：`pos[w..w+2]` 之后又给 `w += 3` 才写法线，等于位置数组每隔三个分量空出一段零 —— 屋面、瓦当这些被烘掉的件全都错位。测试的表现是「五楼射线只有两间打到瓦面」，而构件清单（按档案数件数）照样全绿。修法：同一顶点在两条数组里用同一个下标，`w` 每顶点只加一次。
3. 判定标准也跟着改了：`test/scenes.mjs` 在计时前先空跑一次载入（冷启动的着色器编译不该记到列表第一套模板头上，实测 `cn-palace` 从 3,222 ms 降到 2,410 ms），`test/detail.mjs` 的重建闸门从「fine < 2500 ms」改成「fine < 3500 ms 且 < lite 的 3 倍 + 0.6 s」——绝对值会随内容量涨，真正要防的是档位之间失控。现在的实测：`cn-palace` 切档重建 lite 614 ms / std 1,191 ms / fine 2,306 ms。

面板开关：上述每一块都有对应复选框（`脊兽·檐口椽瓦`、`瓦当滴水`、`台基石栏杆`、`金柱（内槽）`、`檐下彩画`、`平座栏杆`、`檐下斗拱`、`栏板望柱`、`券脸石·螭首`、`影壁`、`抄手游廊`、`登城马道`…），全开就是完整结构；`省内存`（lite）档自动不排脊兽 / 椽瓦 / 栏杆这类细件（实测 `cn-*` 全组 draw 1,638 vs `std` 2,548）。牌楼另有 `间数（1/3/5）`、`明间楼顶`、`柱式（楼式 / 冲天式）`、`平身科攒数`、`匾额题字` 等 19 个参数。

### 25.2 战壕 / 弹坑 / 残楼（11、12）

- **战壕**：木板改成沿沟底通长铺，沙袋压在坑壁口沿，铁丝网挪到胸墙外侧（原来三样互相穿模、木板横搭在沟沿上）。
- **被打烂的楼**：残墙逐段找基座——同一条墙线、沿墙方向有重叠、且不超过本层标高的上一段墙顶就是它的底部，找不到就落到地面（所以断墙是一路从地里立上来的，不会半空浮着一截）；楼板只允许落在**实测墙顶**上（`tops`/`allTops` 逐块记录支撑标高），断梁两端分别搭在墙顶与楼板上、根部塞碎石顶住，洞口统一深 0.26（旧版打穿成缝、楼板悬空无支撑、斜梁穿过残墙）。

### 25.3 石材「三边面断裂」（17，所有自然石材）

根因：`IcosahedronGeometry` / `BoxGeometry` 每个三角形自带三份顶点，旧代码在 `for (let i = 0; i < pos.count; i++)` 里用 `rng()` 逐顶点位移，同一位置的多份顶点各走各的 → 面片彼此脱离，看着像被砸碎。

- `nature.js` 新增 `weld()`（按位置合并顶点）+ `dirNoise()`（连续场：同方向必得同位移）。山峰 / 断崖 / 巨石 / 乱石堆 / 天生石门 / 浮空仙岛 / 太湖石全部改走这条路。
- `weld()` 第一版按 `pos.count` 顺序拼索引，只适用于无索引几何；`BoxGeometry` 因此被炸成一地长条尖刺（断崖实拍可见）→ 改成遍历 `geo.index` 重建三角形。
- 顺带修掉瀑布的 `rng is not defined`（细档 139 件里唯一建不出来的，是我摘逐顶点位移时把 `const rng = makeRng(p.seed)` 一起删了）。

`test/rock.mjs` 的判据：逐块统计「只被一个三角形用到的边」，且**只有成对、几乎重合的边界边**才算撕裂；设计上的开口（雪冠下沿、圆券两端、崖帘边缘）不误报。对照组（同一几何用 `Math.random()` 逐顶点扰动）必须被抓出来，用来证明判据有效。

### 25.4 选中指示器（图 14 的巨大黄圈）

不是模型的问题：`stage.js` 新增 `_boxVisible(root, out)`，选择框与地面黄圈只量**可见网格**，空结果时退回整体包围盒。测试里直接选双开门时 `ringScale=1`、实际尺寸 `2.10×2.39×0.99`，说明原图那个大圈是选中过大物件后指示器未跟着更新的残留。

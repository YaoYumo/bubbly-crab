# 夜景窗灯 · 低成本自发光首版

2026-10-17。按序计划最后一项的首版；不改模型库定义，不逐窗添加实际光源，不捆绑 Bloom。

## 入口与使用

- **全局**：Scene 检查器 →「光影」→「夜景窗灯 · 自发光」，物理天空与经典照明模式下均有入口。
- **单栋**：选中支持的建筑 →「物体参数」→「此建筑窗灯」。默认跟随全局；可以覆盖模式、比例、种子、色温、亮度。锁定建筑不能修改覆盖。选回「跟随全局」会删除本栋覆盖，之后继续响应全局设置。
- 默认「**保持原模型（兼容）**」：不接管材料、不改变旧工程外观；包括原城市模型本来已有的 `lit` 发光。启用新功能请选「随昼夜自动」或「常亮」。
- 「**熄灭**」会将识别出的窗面发光关掉，不关招牌或路灯。「保持原模型」不是“全部熄灯”：它恢复原材质，旧城市模型可能仍自带发光。
- 亮灯比例 **0～1**，默认 **0.65**；种子为 **0～2147483647** 的整数；色温 **1500～10000K**，默认 **3000K**；自发光亮度 **0～8**，默认 **2**，是相对渲染强度，不是流明 / 照度。
- 比例是稳定随机的亮灯概率，**不是精确亮灯户数**。比例 0 全不亮、1 全选中；幕墙仍保留窗格间隔。小模型只有几扇窗时，50% 不保证恰好一半亮。
- 自动模式下，物理天空在太阳高度 **−3°～5°** 间平滑过渡；经典模式跟随旧“夜间窗光 / 灯”的辉光强度。自动模式不会每帧重新掷随机数。
- 「**日景 / 夜景 · 天空 + 自动窗灯**」会一次切换物理天空、手动太阳高度（48° / −12°）和全局自动窗灯，支持一步撤销。它不是仅改窗灯的开关，也不清除已有单栋覆盖。

全局设置与单栋覆盖都随 `.previz` / JSON 保存，支持撤销与重做。保存时只存参数，不烘入发光材质替身。建筑参数重建、灰模显示、ID / 名字、选择和 gizmo 编辑继续沿用原对象。旧工程没有 `light.windows` 时回到「保持原模型」，而不是自动改变夜景。

## 识别范围

仅作用于模型库的住宅风格、郊区建筑、功能建筑和城市建筑类别：

- 原模型已有 `glass` 材质语义的窗面；普通模型按窗组件分组，玻璃和同组件拱窗可共同选择。
- 既有城市写字楼、楼群、住宅板楼、沿街商铺、独栋住宅中采用保守的已知窗材质匹配，不按“所有透明物体”粗暴处理。
- 连续幕墙 / 窗带没有真正分户几何，使用 root-local 程序化窗格；这是视效示意，不是房间、户型或真实建筑开窗的重建。图案未保证与所有楼板 / 裙楼高度精确对齐。
- 已合批的玻璃用 GPU 按现有实例区分亮灯，不拆批、不逐窗增加 mesh。合批后缺失组件语义时，以可用实例为最小单位；拱窗附片等不保证还能绑定为同一户。
- 无兼容窗材质的模型显示窗组数 0，不会把墙、金属或屋顶猜成窗户。原城市模型自己的旧「亮灯比例」参数在新窗灯接管时不再主导窗面；选「保持原模型」可恢复旧参数的原始表现。
- **不自动处理导入模型、车辆、人物、水面、招牌、古建 / 建筑构件及无标记开口及任意第三方 shader。** 不保证所有库模型每一个视觉上像窗的部分都有兼容语义。

普通窗选择使用稳定物体 ID、种子和 root-local 窗组位置 / 朝向：移动、旋转、改名字不会重新洗牌；复制得到新 ID，会得到新的分布。同 ID / 种子及相同构造恢复后保持分布。GPU 实例 / 幕墙哈希在同设备同构造下稳定，不承诺不同 GPU 的浮点哈希逐像素一致；改变精度、模型结构或合批策略也可能改变最小分组。

## 成本、生命周期和材质兼容

- **不新增灯光、投影或几何。** 不对周边地面 / 室内提供实际照明；无 Bloom 光晕、体积光、月亮或复杂夜空。
- 普通窗复用每种原材质的亮 / 暗两个材质替身；合批窗和城市窗面使用已有实例矩阵 / 顶点生成稳定图案与 uniform，不复制顶点数组或逐窗加调用。
- 不原地修改原窗材质，不 dispose 借用的原贴图。重建 / 删除时先还原源材质并释放自己拥有的替身；切回兼容模式也清理接管状态。没有按帧创建材料或重新遍历所有窗几何；未变化的设置只做轻量签名判断。
- 与既有白平衡链和灰模策略兼容：关闭材质显示依旧保留发光。发现并修正了 Basic 灰模复制已带白平衡的 Standard/window shader 导致白平衡声明重复的问题；Basic 使用自己的灰色 / 透明轮廓策略，不复制窗灯着色代码。改种子 / 比例重新创建显示替身、或切回兼容模式时，也会对白平衡注册实际显示材质，验证 3200K 非中性白平衡链不丢失、不重复。
- **低内存 Basic / 关闭光影模式不显示窗灯**；恢复标准光影后恢复窗灯。不是为了发光而另加一个覆盖绘制通道。
- 建筑不透明墙体仍可走原实例化；自定义窗灯 shader 不强行纳入不安全的跨对象合批，已有窗用原实例绘制。实际节省量依场景、阴影和裁剪而变。
- 自定义程序窗格属于本工具渲染效果；不承诺外部 glTF / OBJ 等格式能携带这些自定义 shader。工程参数恢复和工具自己的预览渲染不受此限制。

## 本轮验证

`window-lights.test.mjs` 与源码 / 正式 `file://`（浏览器断网）专项通过：

- 配置范围与非法值、稳定随机概率、0 / 1 边界、源材质不变、几何引用不变、有界亮 / 暗替身、灰模与兼容模式切回、释放。
- 3 栋 Adobe（普通 + 两栋合批）和 1 栋城市塔楼，400×260 固定相机、相同夜景设置：亮灯前后 **306 → 306 calls、10,202 → 10,202 三角形、13 → 13 场景光源**。13 包含既有太阳、补光及灯具池，窗灯增加量为 **0**。
- 普通窗组、合批实例窗及城市程序幕墙都能实际渲染；相同种子画面复现、不同种子可见变化；反复改种子 / 比例不持续增加 geometry、program 或材质数。
- 同一个亮灯场景，启用不透明建筑实例化后 **306 → 113 calls**，三角形均 **10,202**；画面对照在原专项容差内。软件渲染短样本，**不是硬件 FPS 承诺**。
- 单栋覆盖不影响邻栋、日夜自动、灰模 shader 链、Basic 切换恢复、全局撤销 / 重做、实际 `.previz` 保存恢复、旧项目兼容、重建后覆盖保持、名字 / ID / 顺序 / gizmo、原生 UI、PNG 抓帧、日夜按钮一步撤销与锁定保护，以及清空后所有窗灯自有材质释放。

双构建完成，保留现有大 chunk 提示。相关回归的该阶段完成状态、原始报告和当时正式 HTML 大小 / SHA256 见 [window-lights-evidence/manifest.json](window-lights-evidence/manifest.json)。未运行全部历史总门禁，也未做跨 GPU 画质或硬件性能验收。先前 `ordered-development-evidence` / `road-diagnostics-evidence` 保留各阶段历史包的哈希，不覆盖成当前版本证据。

## 复现

先启动开发服务 `npm run dev -- --port 5174`，然后：

```sh
node test/window-lights.test.mjs
bash test/withchrome.sh node test/window-lights-regression.mjs
npm run build
npm run build:single
TEST_FILE_URL="file://$(pwd)/previz-lab.html?fresh=1&benchmark=1" \
  bash test/withchrome.sh node test/window-lights-regression.mjs
```

测试只使用新建临时浏览器页面，不要替换为已有工程页面。

# 1.8.0 四项综合回归证据

`web.json`、`file.json`、`desktop-csp.json` 来自最终源码的真实 Chromium 综合回归；file 模式禁网。测试脚本为 `test/road-traffic-regression.mjs`。

- 同样的源道路场景换回旧版支撑计算时只有 2 根；最终螺旋支撑为 7 根，间距 7.2m，实体柱／帽与所有道路三角面的碰撞为 0。缓存与保存载入后的站位一致。不是保证整个环每处都能放柱：额外调试中禁用真实道路碰撞后会放出 13 根，其中多根穿过螺旋的下层返回段／地面道路，正式实现会继续拒绝这些位置。
- 两个紧凑汇入口各 4 段虚线，无高速斑马线／城市停止线。对每个导流三角面中心向真实场景路面发射射线，包括原道路与补片接缝，标线高出路面约 8mm，没有被更高铺装掩埋。
- 真实键盘依次输入车道宽 4.2m、4 条车道、路肩 0.8m；输入节点／焦点未被事件刷新替换，参数正确，临时 draft 面板闪现计数为 0。
- 实际 UI 开启交通；真实路网红灯停车、绿灯释放；普通道路、园路及高架高速类型约束；实例化；撤销／重做／保存／载入；暂停保持；反向时间 seek 后 GPU 实例跟随新的演员引用；真实 PNG 导出结束恢复原交通位置均通过。`supports.png` / `traffic.png` 是 Linux 软件 WebGL 的示意截图，不是 Windows 视觉验收。
- `road-performance.json` 是既有道路性能专项：几何像素差 0，局部地形只重建 1 条路、远处不重建，保守批处理 356→82 draw calls（同 11,462 三角面），桥墩缓存命中 18。不是 RTX4070Ti 的帧率测试，也不是自动交通开启时的性能承诺。

此外跑过旧接头／锐角／高度柄、8 组匝道路由、12 视角中央带（含旧重叠负对照）、三模式螺旋，以及纯测和三种构建。Windows 安装／启动证据另见 `../desktop-1.8.0-evidence/`；完整工程级交通、用户 GPU 和真实本地 GGUF 未验收。

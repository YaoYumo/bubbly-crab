# 拾取空间索引 · CPU 候选筛选首版

2026-10-17。只优化编辑视图的 `Stage.pick()`，不改变工程格式、模型库、渲染代理或选择对象。无 LOD、Bloom、避让索引或三角形级 BVH。

## 使用

默认开启，无需重存工程。工具栏 **性能 → 拾取索引：开 / 关** 可在当前页面对照原路径；关闭时执行原 `world + helperLayer` 全树递归射线检测。开关只保存在当前运行态，不写工程 / 撤销历史，刷新回到默认开启。

诊断面板与导出 JSON 的 `picking` 显示：

- 最近一次查询的候选 / 全部**顶层根节点**数量（含辅助层，不是网格数、对象数或三角形数）。
- 是否包含冷构建、是否待失效重建、保守回退根节点数。
- CPU 同步 / 冷构建、候选筛选、精确射线检测与总耗时。不是 GPU 时间或持续平均点击延迟；未查询时为空。失效后的“上次”数据不代表新场景的查询结果。

## 实现和兼容

1. 对可确认安全的静态对象，合并其原始 Mesh / 静态 InstancedMesh 的保守包围盒，建立 root-local AABB 缓存和世界空间中位数划分 BVH。
2. 每次查询检查顶层根节点身份、顺序、分类、直接子节点数量和根变换。根移动 / 旋转 / 缩放时更新后代世界矩阵、重算世界 AABB 和树；不逐帧重建。
3. 射线先查询 AABB 候选，再按原 world / helper 根顺序调用 Three **原始对象**的精确递归 raycast；仍按真实命中距离排序，不把最近包围盒当作命中。保留等距稳定次序。
4. 命中处理与旧 `Stage.pick()` 一致：叶子 `pickIgnore`、key、祖先 `so`、祖先 `shotRef`、ground，再到 empty / 原地面交点。保留原 `so` / root 引用、ID、point / distance、选择和 gizmo。建筑渲染实例代理不代替源物体参与选择。
5. 不新增 `visible` 过滤：Three 旧射线检测不按此字段裁剪，隐藏对象的既有命中行为继续保持。没有顺便改变这项旧语义。

以下保留原精确路径：人物、活动物体路径、动画、蒙皮 / 变形目标、动态顶点或动态实例缓冲、自定义 raycast / 顶点访问、Line / Points / Sprite、不可靠 / 空包围体及退化根变换；辅助层和相机机位也保守回退。非标准 world / helper 容器 raycast 会使整个查询回退。建索引异常时当次回退，并在诊断 JSON 记录原因，不吞掉原精确 raycast 本身的异常。

仅跳过可证明不产生可接受命中的叶子：默认无子节点 Object3D（如空路径标记组）、默认 Mesh raycast 的 `pickIgnore` 叶子、旧接受规则不会选中的无对象标记 terrain 叶子。地面、机位和关键帧仍走原语义。

### 失效和生命周期

- 内建 `objects / terrain / gizmo-live / shots` 事件使索引失效，立即清除旧 entries / tree；参数重建、删除、撤销、工程导入、地形贴合和机位删除不会由索引继续持有旧根节点。
- 几何包围体缓存为 WeakMap；不复制几何顶点，不增加 GPU 几何 / 材质 / 光源或 dispose 借用资源。
- **外部脚本**直接修改深层子节点、几何或实例矩阵，须按 Three 的要求更新属性 / 包围球，并调用 `app.stage.pickIndex.invalidate('external edit')`，或发出正常 `objects` 事件。仅修改根变换会在下次查询自动检测；不是全场景代理监听器，未承诺无事件的任意深层变更自动失效。
- 树查询可以剪枝，但每次仍需 O(顶层根数) 的一致性 / 根矩阵检查。大范围根移动或编辑后的下一次查询仍有建树成本。单个巨大植被组内部、动态对象和辅助对象仍保留递归检测，不保证所有场景都同幅度加速。

## 测量口径

`test/pick-spatial-index-regression.mjs` 在独立临时基准页构造四个固定 fixture，960×540 / DPR 1 / std，渲染预热 **8 帧 + 采样 30 帧**。每个 fixture 另测原路径与新路径：

- 独立复制旧接受逻辑，不用新 resolver 充当唯一参考；比较 kind、对象 / shot / key 引用、交点、距离，并检查工程序列化和选择不变。
- 35 个固定屏幕射线，加最多 14 个对象投影射线。包含命中与落空，不只对准建筑中心。
- 首次旧路径与冷索引查询单列。随后每条路径预热 8 个完整射线批次，**30 批交替 A/B 顺序**；每批平均每射线墙钟时间，报告这些批均值的 mean / p50 / p95。**p95 是批均值的 p95，不是单次点击尾延迟**。
- 冷构建会使用同进程 / 同场景引擎已有缓存，不是浏览器全冷启动。热 A/B 共享已计算的 Three 几何包围盒，对原路径也是有利条件。
- Chromium 131 / ANGLE SwiftShader 软件渲染。CPU 拾取收益不是 FPS 提升，不代表用户显卡 / 硬件性能；原始批次和渲染报告一并保留。

### 本次四场景结果

单位 ms；热查询为 30 个批均值的均值。DEV 和真实断网 file 均完整执行 8＋30 渲染采样及拾取 A/B，分别 **204 组语义对照**，其中 96 组为对象命中，另通过原生鼠标选择 + gizmo。没有用 smoke 代替正式结果。

| 场景 | 热查询 DEV，原 → 索引 | 热查询 file，原 → 索引 | 平均候选 / 全部根 | 冷查询 DEV / file |
| --- | ---: | ---: | ---: | ---: |
| 普通小镇 | 0.576 → 0.041 | 0.630 → 0.040 | 3.47 / 41 | 5.5 / 5.3 |
| 密集城区 | 1.060 → 0.070 | 1.154 → 0.081 | 3.55 / 121 | 18.3 / 22.5 |
| 地形植被 | 2.013 → 0.187 | 1.796 → 0.168 | 2.63 / 9 | 40.1 / 17.7 |
| 夜景多灯 | 0.705 → 0.065 | 0.738 → 0.068 | 3.86 / 103 | 5.7 / 7.2 |

密集城区热查询约减少 **93% CPU 墙钟时间**；不是 93% FPS 提升。冷查询是第一条固定射线（可能落空）加全场景索引同步 / 构建，**可能明显慢于原路径**；编辑后的下一次点选也要承担冷重建，未实现后台 / 空闲预构建。本轮不以单次最小值或热均值承诺所有点击延迟。

两入口的四场景 30 帧 calls / triangles 均保持：**584 / 117230、1586 / 344078、177 / 646522、722 / 66226**。索引不减少渲染绘制调用，历史绘制优化保持不变。

Node 专项 **647 组**精确结果对照，另检验蒙皮 / 不支持类型回退和立即释放；覆盖等距顺序、隐藏旧语义、ignore、层 / near / far、key / shot / ground、根变换、深层编辑失效、实例、动态与自定义回退、异常和启停。浏览器专项另覆盖实例化源对象、原生选择、gizmo、撤销 / 重做、重建、负缩放、隐藏、活动路径、相机回退与删除、窗灯 / 灰模、诊断原生开关、真实 OBJ 和工程包往返、ID / 顺序 / 资源 ID、地形贴合及删除 / 清空。

实际结果、验收范围及本阶段正式单文件哈希见 [pick-spatial-index-evidence/manifest.json](pick-spatial-index-evidence/manifest.json)。旧阶段 evidence 保持历史，不覆盖成当前结果。

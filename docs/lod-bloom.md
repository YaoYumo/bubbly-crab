# 远景 LOD 与可选 Bloom · 首版

2026-10-18。入口：**Scene → 光影 →「远景 LOD · 建筑细节」/「Bloom · 高亮泛光」**。新旧工程均默认关闭，需主动开启；两个效果独立设置，也能同时开启。设置写入工程顶层 `rendering`，支持 UI 撤销 / 重做和 `.previz` 工程包恢复。旧文件缺此字段时保持原渲染。

## 远景 LOD

- 作用范围：静态模型库住宅、郊区、功能和城市建筑。人物、运动路径、动画、道路 / 地形、植被组、导入模型及不安全的自定义渲染对象不纳入首版。不是全场景自动重拓扑。
- 默认中景 **90m**、远景 **200m**；按根节点世界位置与最终渲染相机距离选级，距离切换有约 10% 滞回。近景全精度；中景保守、远景较强地简化。选中物体始终用原精度，避免编辑时对着简化替身操作。
- 同时依据相机投影、屏幕高度和缩放估算构件尺寸。默认远景阈值 **1.5px**，中景阈值为其一半，忽略小于阈值的微小不透明构件。不会按距离直接设置整栋 root 隐藏；不保证亚像素构件仍然可见。
- 其余适合的三角网格以 **24 / 10 格顶点聚类**生成两级派生几何；保留法线方向、UV 分块和颜色边界。不支持的属性、多材质、变形目标、动态缓冲、自定义 shader / mesh 回调等保守回退。透明玻璃、发光窗和自定义窗灯 shader 不简化，避免将窗灯压成粗糙亮块。
- 大于约 **220px** 的构件不做几何简化，即使根节点距离较远；较大屏幕投影保留细节。正交相机使用正交投影的像素尺寸，不套用透视 FOV。
- 只在一帧渲染事务内替换几何 / 可见性，包含该帧阴影与景深深度通道；成功或抛错均恢复原引用。点选仍用原几何与原空间拾取索引，ID、参数、选择、gizmo、撤销与工程资源不被替换。
- 与建筑实例化共存：相同低精度几何可共享实例代理；同批里若近 / 远景几何混合，则回退源物体绘制，不错误套用原高精度代理。**混级时 calls 可能升高**，不是任何相机都能同时最大化合批与减面。

### 缓存与代价

按内容哈希定位、逐字节复核几何后共享派生结果，避免仅凭哈希碰撞替换模型。最多 128 个源几何缓存项、派生属性 / 索引数据约 **8 MiB** 上限；这是 CPU 数组字节估算，不等于全部内存 / 显存。

每帧最多开始构建 2 个派生几何，在每次开始前检查约 4ms 软预算；单几何限 120–12000 顶点。**不是 4ms 硬时限**：遍历、哈希、单次聚类和上传仍可能超过预算。新开启 / 场景编辑后会逐帧预热，没有阻塞等待所有模型一次生成完毕。关闭 LOD、对象 / 地形 / 光影 / gizmo 编辑时清理自有几何，不 dispose 借用的源几何 / 材质。

这是近似视觉 LOD，不是保拓扑 / 保体积 / 测绘精度的离线网格简化；远景轮廓、UV、法线、小孔和阴影可能改变，没有交叉淡入淡出。阴影跟随主相机所选级别，不按每盏投影灯分别选级。单个巨大合并网格、透明 / 发光 / 程序窗面和预算外几何可能不减面。外部脚本深层改源几何后，应按 Three 规则更新属性 / 包围体并调用 `app.renderEffects.lod.invalidate()`；如影响拾取，也需使拾取索引失效。

## Bloom

- HDR 高亮提取 + 多级模糊（Three UnrealBloomPass），在景深之后、既有宽银幕效果和 OutputPass 之前合成；最后统一 tone mapping / 输出编码，不另外叠一次相机白平衡或曝光。
- 默认：强度 **0.35**、半径 **0.25**、阈值 **1.1**、中精度。强度 0–2、半径 0–1、线性 HDR 阈值 0–10；不是显示器 RGB 亮度阈值。夜景可先用默认值，再结合曝光和窗灯强度调整，避免整片泛白。
- 低 / 中 / 高分别使用标准 Bloom 输入的 **1/4、1/2、1 倍**尺寸。UnrealBloomPass 自身高亮目标还会减半；例如 400×260 输出时，低 / 高首级高亮目标约 50×33 / 200×130。主合成器仍保留完整输出尺寸。
- **是全屏高亮 Bloom，不是只允许窗户泛光的选择性遮罩。** 窗户、路灯、招牌、天空或明亮反射都可能超过阈值。不新增实际光源，不照亮地面或室内，不产生遮挡、体积光、星空或复杂夜空。
- 关闭 / 强度为 0 时移除并释放 Bloom 自有目标与材质，走原路径；低内存 Basic 模式暂停 Bloom、保留设置，恢复标准模式后重新创建。缺少 HDR 颜色附件扩展时保留参数并跳过 Bloom，诊断面板说明原因；设备支持恢复后可重新运行。既有合成器和导出拷贝资源仍可能驻留，不承诺全部显存归零。
- 与景深、既有宽银幕效果、灰模窗灯、3200K 白平衡、DPR / 导出尺寸切换共同验证。带黑边输出先渲染内框到后处理目标，再拷贝最终结果到内框，不让光晕污染黑边；PNG 和视频共用此路径。连续同尺寸视频帧保持内框目标尺寸，避免每帧在内框 / 全画布之间重新分配；回到普通渲染时才同步到恢复后的画布尺寸。
- Bloom **增加**离屏目标、GPU 通道和内存带宽；合成器与直接画布的抗锯齿路径也可能不同。需要本工具现有 HDR 后处理支持，不是免费性能优化。

## 本次测量

Chromium 131 / ANGLE SwiftShader 软件渲染，12 栋合批 Adobe，400×260、固定相机、禁用阴影以隔离观察；不是旧四场景固定基准，也不是硬件 FPS 验收。LOD 预热 35 次，再各路径预热 8 次、采样 30 次 `Stage.render()` JS / 驱动提交墙钟；Bloom 也各路径 8＋30。两路径依次运行，不宣称统计意义上的硬件基准。耗时含驱动等待，不是纯 CPU 或纯 GPU 时间。

| 项目 | 原路径 | LOD | LOD + Bloom |
| --- | ---: | ---: | ---: |
| 绘制 calls | 282 | 276 | 290 |
| 提交三角形（含后处理） | 40,286 | 35,102 | 35,116 |

源码与实际断网 file 结果一致：LOD 提交三角形减少约 **12.9%**，28 个微小构件省略、48 个 mesh 使用派生几何；派生属性 / 索引合计 **15,712 字节**。同一远景视图 RGB 平均绝对差 **0.03895 / 255**，约 0.254% 通道差值大于 3，最大差 64；仅覆盖此固定视角，**不是画质完全不变**或所有模型 / 角度验证。

| 提交墙钟均值 ms（30 样本） | DEV 原 → 开启 | file 原 → 开启 |
| --- | ---: | ---: |
| LOD | 7.443 → 6.817 | 7.353 → 7.467 |
| Bloom | 7.967 → 8.593 | 7.637 → 10.507 |

**LOD 未测得跨入口稳定的提交耗时改善**；file 均值反而更慢，所以只确认此场景减面，不将减面率当作 FPS 增益。首次 LOD 准备约 **30.0 / 28.5ms**，有冷启动代价；稳定后准备约 0.7–0.8ms。Bloom 单独使 calls **282 → 296**，增加 14 个全屏绘制，夜景像素均差约 **2.296 / 255**；增加的 14 个“提交三角形”来自全屏通道，不是新增场景模型。

完整数据与 p50 / p95、缓存、像素差、两效果同时开启和导出冒烟在 [lod-bloom-evidence/manifest.json](lod-bloom-evidence/manifest.json)。性能面板新增最近 LOD 计数、派生缓存字节和实际高亮目标尺寸，不把这些数字当作 GPU 实测。

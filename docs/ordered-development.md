## 路口门禁根因与修复

原失败点为 30°、600m 高度、0.8 倾角、第四个步道中心，RGB `[118,137,156]`。射线确认该像素对应步道；隐藏车行底面后恢复 `[200,212,223]`，隐藏侧墙或取消侧墙偏移没有改善。因此不是阈值、步道采样点、材质颜色或阴影开关问题，而是路口完整车行底面仍在步道下，远景深度量化 / 斜率偏移使它反盖更高的步道。

`junction.js` 现从凸轮廓车行面减去步道区域，使用已有 Clipper 整数布尔运算、严格简单轮廓、20μm 级取整尖刺清理，再按带孔多边形三角化。保留路口标高、材质颜色、相机和原像素断言。`junction-regression` 只增加正式离线入口支持，未放宽阈值或删除样本。

验证：

- 原门禁 **6 角度 × 3 距离 × 2 倾角 × 4 步道角块**，源码和最终单文件全部通过。
- 新 `junction-surface.test.mjs`：6 角度 × T / 十字 × 不等路宽、非零世界坐标，检查面积守恒及步道中心下无车行顶面。
- T 路口真实绘制 / 恢复、旋转 / 端点 / 顺序、路口材质与地形道路全体积碰撞专项通过。

[上一轮道路专项](performance-roads.md)中保留的 FAIL 是修复前历史记录，不代表本阶段仍失败。

## 建筑实例化首版

### 行为与范围

默认自动启用，覆盖模型库的住宅风格、郊区建筑、功能建筑类别中的兼容静态零件；没有修改模型库定义。导入模型、角色、骨骼 / morph、自定义 shader / mesh 回调、透明 / 特殊深度材质等不安全路径不强制实例化。只有同资产、同空间块里至少两个逻辑物件具有完全兼容的部分才形成实例批。

- **原对象仍是唯一编辑 / 拾取 / 保存表示**：不改 SceneObj 的名字、ID、参数、根节点或序列化格式。代理禁止射线拾取，继续通过原零件拾取到原对象；gizmo 仍绑定原根节点。
- 只在主场景 renderer 调用期间隐藏被替代源零件，使用实例代理提交，在 `finally` 恢复可见性；普通视图、后处理原场景通道和导出共用这一入口。非主场景、不兼容 shader override 不走代理。反射 / 剪切等不安全变换回退。
- 64m 空间分块；精确比较几何属性布局、索引 / 属性字节（hash 后再次完整比较）、groups / drawRange，以及材质全部绘制属性、纹理身份、阴影 / 层 / 排序标志。不按近似颜色合并。
- 只识别自有相机白平衡包装器，保留原 shader hook 身份；外部替换包装器不会被误认作默认 shader。
- 刚体移动更新实例矩阵 / 包围体，跨块、删除、显示策略、参数重建、光照或地形依赖变化失效重建。负缩放 / 非正交变换等保留普通绘制，避免实例法线或正反面错误。
- 代理借用原几何 / 材质，不单独释放它们；代理移除时调用 `InstancedMesh.dispose()` 释放自己的实例资源。原始几何仍保留，因此不是 CPU 场景内存减半或全局资源所有权改造。

### 裁剪保护

简单空间批处理曾使夜景提交三角形增加，故未直接交付该路径。现逐批检查当前主相机及实际投影灯的阴影视锥（点光源逐立方体面）；如果批内成员会被不同裁剪，或者合并包围球产生额外的可见命中，该批本帧使用原绘制。这比无条件大批处理保守，但避免为了减少 calls 而扩大本轮基准的三角提交量。

性能面板显示最近一帧实际替代的批数 / 源网格数；一次性绘制归因正确归入原建筑类别。无 LOD、无空间拾取索引，仍保留原对象更新、射线检测和矩阵 / 包围体 / 视锥检查成本。

## 道路检查器（上一阶段交付）

选中已完成道路，在物体参数中展开「道路检查 · 标高 / 纵坡 / 净空」，手动运行。支持沿线基准标高 / 有符号纵坡 / 最大绝对纵坡、实际路面地形穿入、不同道路及上方路口铺装的净空、桥墩受阻定位、前次检查摘要差值和 JSON 导出。**基准标高不是沥青完成面，阈值不是工程合格线。**

检查按需异步进行，支持取消；场景 / 阈值变化使旧结果失效。不改工程和撤销栈，不逐帧扫描，不保存诊断辅助对象。最多 1025 个纵向站 × 9 个横向点，有明确预算及采样边界。

源码及真实 `file://` 网络离线专项通过；实际道路 / 地形 / 区域规划 / 实例化 / 性能断言、正式文件道路参数 / 规划 / 照明回归，以及正式文件原 6×3×2×4 路口门禁保持通过。未跑全部历史总门禁。

使用方式、采样定义和完整限制见 [road-diagnostics.md](road-diagnostics.md)，道路阶段当时结果及 HTML 哈希见 [road-diagnostics-evidence/manifest.json](road-diagnostics-evidence/manifest.json)。各阶段 evidence 均保留历史快照，这些清单描述各自历史包，最新拾取阶段见文末。

## 夜景窗灯（上一阶段交付）

Scene → 光影 →「夜景窗灯 · 自发光」，支持 0–1 亮灯概率、稳定随机种子、1500–10000K 色温、0–8 自发光亮度，以及自动 / 常亮 / 熄灭 / 保持原模型模式。日 / 夜按钮同时设置物理天空和自动窗灯；单栋可以覆盖，锁定保护、撤销和 `.previz` 存档保持。

普通窗复用亮 / 暗材质，合批窗按已有实例在 GPU 选择，城市连续幕墙用程序窗格；不新增几何、真实光源或投影。没有修改模型库定义。灰模保留发光，Basic 低内存模式不显示，切回标准后恢复。兼容默认值「保持原模型」不主动改旧项目。

普通 + 合批 Adobe 和城市塔楼固定视图 A/B：开灯前后均 **306 calls / 10,202 三角形 / 13 个既有场景光源**；开启不透明建筑实例化后 **113 calls / 10,202 三角形**。这是 Chromium 软件渲染的短样本，不是硬件 FPS 承诺。既有四个性能 fixture 的 calls / 三角形保持 584 / 117230、1586 / 344078、177 / 646522、722 / 66226。

本轮源码及断网 `file://` 窗灯专项、相关兼容性回归和双构建的证据见 [window-lights-evidence/manifest.json](window-lights-evidence/manifest.json)，该窗灯阶段当时的 `previz-lab.html` 大小 / SHA256 也保留在该清单中；后续正式包见文末。功能边界、复现及使用方法见 [window-lights.md](window-lights.md)。没有跑全部历史总门禁。

Bloom、真实室内照明、复杂夜空和导入模型自动识窗没有实施，不将其包含在首版完成范围里。

## 后续：远景 LOD + 可选 Bloom（最新首版）

按最新授权增加两项独立效果，入口 Scene → 光影；默认关闭，主动开启后参数随工程保存并支持撤销 / 重做。LOD 仅作用于安全的静态库建筑，近景 / 选中物体恢复原精度；按距离和投影尺寸做微小构件省略与两级顶点聚类。原几何、ID、选择、gizmo、拾取和资产不被替换，渲染成功 / 异常均恢复源引用；与实例化同级共享、混级保守回退。

Bloom 全屏 HDR 高亮提取 + 模糊，参数独立，支持精度、DPR、景深 / 宽银幕组合和带黑边的 PNG / 视频路径；低内存及缺少 HDR 支持时安全暂停，不新增实光。

12 栋固定远景：282 / 40,286 → LOD 276 / 35,102（calls / triangles），再开 Bloom 为 290 / 35,116。LOD 减少约 12.9% 提交三角形，但没有跨入口稳定提交时间提升；Bloom 增加通道和成本，均不承诺硬件 FPS。DEV 与断网 file 专项、预算 / 释放、保存 / 撤销和相关兼容性见 [LOD / Bloom 说明](lod-bloom.md)。**最新正式包**、本轮执行清单与源指纹见 [lod-bloom-evidence/manifest.json](lod-bloom-evidence/manifest.json)，先前清单保持历史。未运行全部历史总门禁。

首轮数据保留为历史基线。最新两项道路优化、前后对照及未通过的旧路口门禁见 [道路性能专项](performance-roads.md)。

## 使用

1. 打开现有开发预览，或双击最新 `previz-lab.html`，点击工具栏 **性能**。
2. 普通面板只观察当前工程，不修改内容。可暂停 / 重置采样，导出当前诊断 JSON。模态窗口拦截编辑快捷键；关闭后继续编辑。
3. 点击 **打开独立基准标签页**。链接由当前入口构造，兼容代理预览地址和 `file://`，不依赖额外服务器、网络服务或上传。
4. 在新标签页点击 **运行 4 组固定基准**。请保持它在前台；后台节流会中止本轮。此页强制 fresh，不自动恢复存档；所有自动存档入口统一拒绝写入，原标签页工程不被替换。浏览器若阻止新窗口，可通过链接的标准“在新标签页打开”操作进入。
5. 可取消任务；已完成场景仍可导出 JSON。同步模型生成、地形分类或压缩任务不能在指令中途被强制抢占，取消会在可检查的让出点生效。测试完成 / 取消后清空测试工作区，不恢复或覆盖原标签页。

性能面板新增 **测一帧绘制归因**：按模型种类 / 道路 / 桥墩分列主场景与阴影回调次数，显示最近一次结果和 renderer 差额；非 GPU 计时，差额可能为负，详见道路专项。

采样只保存在内存中；报告需手动下载。不自动上传设备、场景或性能数据。导出的 JSON 包含浏览器 / GPU 标识和视口参数，便于同设备对照。

## 统计口径

- **实际 FPS / RAF 间隔**：来自未限幅的 `requestAnimationFrame` 时间戳，含调度、主线程阻塞与呈现等待。动画仍单独保留 60 ms 步长上限，避免一次跳太远；不再把限幅后的动画步长当作 FPS。
- **更新 / 渲染提交**：`performance.now()` 包住更新与 `stage.render()`。包括 JS 和驱动同步等待，不是纯 CPU 执行时间，更不是 GPU 帧耗时。不要用 `1000 / 提交耗时` 推导 FPS。
- **GPU**：浏览器支持 `EXT_disjoint_timer_query_webgl2` 时异步读取最近完成查询；disjoint 时丢弃。不可用时明确显示不可用，不能用 CPU 时间补填。沙箱 Chromium / SwiftShader 无此扩展，实际硬件查询仍需真实设备验收。
- **多通道**：每帧开始保存 `renderer.info.autoReset`，显式 reset，暂时禁用各 render 的自动 reset；结束在 `finally` 恢复，采集阴影、主场景和后处理累计调用及三角形。不会永久改变导出路径的 renderer 状态。
- **资源**：`renderer.info.memory` 是渲染器已上传驻留的几何 / 纹理计数；程序来自程序缓存。场景引用材质 / 几何 / 纹理去重计数另列；属性和纹理字节只估算当前引用，未涵盖所有离屏目标、源缓存、压缩 / 格式差异和驱动开销，不是 VRAM 实测。浏览器 JS heap 也不是本工程独占内存。
- **操作耗时**：地形生成 / 网格更新 / 自动分类、贴地、道路重建 / 桥墩更新、模型重建、工程序列化 / 打包 / 恢复、天空反射更新。全部含子调用；异步打包含等待，不可把这些耗时相加。当前更新 / 渲染统计不能单独归因到每一种模型。
- **启动**：构造耗时覆盖 `new App()`；首帧为首次提交；就绪时刻相对页面时间原点，包含模块加载 / 存档恢复确认等待，并非纯渲染启动耗时。模块下载前的细分未独立剖析。
- **有界成本**：最近 240 帧、40 条操作记录、最多 32 个操作标签；普通循环不遍历整个场景来统计材质。面板每秒刷新时才计算引用统计，或导出时显式计算。诊断和进度 UI 自身也会有少量开销，不宣称零开销。

## 固定基准 v1

共同参数：种子 731、160 m 地形范围、std 模型精度、表面贴图开启、PBR 物理天空、46° 透视、960×540 像素、DPR 1、天气与后处理关闭。清除预览 / 自动旋转 / 轨道阻尼残量；辅助显示和网格不参与。每组首帧提交单列，再预热 8 帧、采样 30 帧（29 个相邻 RAF 间隔）。各组按顺序复用引擎缓存，构建不是全冷浏览器启动。

| 场景 | 固定内容 | 地形 / 相机 |
| --- | --- | --- |
| 普通小镇 | 12 栋 adobe、24 株行道树、4 路灯、2 道路 | 地形关闭；65 网格；相机 `[88,70,110]` |
| 密集城区 | 48 栋 adobe、8 路灯、4 道路 | 地形关闭；65 网格；相机 `[88,70,110]` |
| 地形植被 | 600 株实例行道树、2 条跟随道路 | 129 网格、hills / amp 12 / seed 731；相机 `[88,70,110]` |
| 夜景多灯 | 12 栋 adobe、32 路灯、4 双灯宫灯、2 道路 | 地形关闭；65 网格；相机 `[15,10,28]` |

相机目标 `[0,2,0]`。白天太阳仰角 48°，夜景 −14°；均衡灯光预算 8 实光 / 1 灯具阴影，夜景实际候选 40、启用 8，其他灯保持预算策略。其他天空参数和实际资产 key 写入报告；布局不使用随机 UID 决定几何。完整清单见 `src/performance-benchmarks.js`。

建造按每四个资产让出一帧；植被单批实例化。工程打包后实际异步解包，再通过 `loadJson` 恢复，恢复计时包含解压、场景重建和既有 tick 渲染。地形场景另做一次固定笔刷编辑及道路 / 植被联动；首轮这条编辑耗时包含当时的道路全量重建；后续已改为保守组件增量更新，见道路专项，不代表所有编辑卡顿已经消失。

## 2026-10-16 沙箱参考（首轮历史记录）

原始数据保存在 [performance-baseline.json](performance-baseline.json)。环境是 Headless Chromium 131 / ANGLE SwiftShader 软件渲染；GPU query 不可用。下表是正式离线单文件通过原生按钮运行默认 **8 帧预热＋30 帧采样** 的结果，单位 ms；单轮测量有波动，不是设备评级。

| 场景 | 全通道绘制调用 | 三角形 | 提交 p50 / p95 | 真实 RAF 平均间隔 |
| --- | ---: | ---: | ---: | ---: |
| 普通小镇 | 2,160 | 117,230 | 20.2 / 36.7 | 852.3 |
| 密集城区 | 6,846 | 344,030 | 68.7 / 96.6 | 2,054.5 |
| 地形植被 | 869 | 646,522 | 10.7 / 15.7 | 2,604.5 |
| 夜景多灯 | 1,075 | 62,542 | 19.0 / 24.4 | 1,418.3 |

**提交耗时与真实帧间隔相差很大，正说明不能把 CPU 提交当 FPS，也不能把软件渲染沙箱当用户 GPU。** 首轮先解决测量准确性与明确资源问题；表中低帧率不意味着已通过整场景流畅度门槛。

### 本轮优化证据

- 修复前 400 株、12 轮 `terrain.refresh + vegetation.refit` 的初步冷样本：根节点替换 12 次，旧实例网格 dispose 回调为 0，总 CPU 调用 121.6 ms。此单次全链路样本不能与下述隔离测量直接比较；初步优化后该全链路单样本约 169.8 ms，波动及分类 / GC 成本使其不足以证明整体加速。
- 同进程隔离对照：复现原先“每次重建”算法，与原位贴地比较。400 株 × 12 调用，五轮中位数；两种算法共用当前释放逻辑，不包含 `terrain.refresh`、UI 或渲染：

  | 条件 | 重建算法 | 原位 / 跳过 | 结论 |
  | --- | ---: | ---: | --- |
  | 高度未变 | 29.5 ms | 0.4 ms | 避免无意义重建 |
  | 高度交替变化 | 15.1 ms | 12.3 ms | 保持同一根节点、几何、材质与实例缓冲，减少分配抖动 |

- 实例矩阵更新后重算包围盒 / 球，支持根节点平移、旋转和非均匀缩放。材质显示策略、选择和 gizmo 绑定保持；株数 / 种类变化的擦除以及精度切换仍重建。
- `disposeDeep` 补齐每个 `InstancedMesh.dispose()`，并在同一树内去重释放共享几何 / 材质 / 纹理。不是全局纹理引用计数改造，也未声称所有缓存均可清零。
- 预览点固定 160 容量、动态 attribute 加 drawRange，反复更新 / 停止不再换 position 缓冲。
- 五轮生成 / 删除 / 撤销 / 重做 / std↔lite、灯光质量和天空切换后，几何稳定 31、程序稳定 22，纹理随档位在 7 / 4 间切换。保留 helper 和引擎缓存是预期，不能把非零资源计数直接认作泄漏；这也不是任意长时重型工程的完整泄漏证明。

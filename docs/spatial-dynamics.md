# 场景配方第二批 · 数据关系与动态约束首版

2026-10-20。在[第一批两类配方](scene-recipes.md)上，加入可复用的数据关系求解器、时序控制和更明确的检查报告。仍然本地离线，不调用真实 AI 或付费 3D 服务；没有扩展 AI plan v1 的字段。

## 界面怎么用

**Scene → 一句话生成 → 配方参数**：

- **行人路径倍率**：0.5–2。改变沿路径的推进速度，不改路线形状；不等同于走路骨骼动画的 `motion.speed`。
- **飞车路径倍率**：0.5–2，仅赛博配方显示。
- **种子错峰出发**：为各动态对象计算可复现的起始相位；不是自动避碰，部分安排可能反而让车辆更接近。
- **预览布局**下新增关系／动态摘要，说明局部挂接、地块留空、路线及扫掠检查数量；展开「动态提示」看接近风险、时间轴循环接缝。

支持文本，例如：

```text
赛博都市，4辆悬浮车，6位行人，行人速度0.5倍，飞车速度2倍，错峰，种子82
```

```text
中式古城沿河，6位行人，行人速度1.5倍，错峰，种子42
```

也支持「行人慢走／行人快走」「飞车慢行／飞车加速」「关闭错峰」。只在已识别配方时使用这些参数；速度词本身不会把普通造镇劫持成古城。

**非整数倍率的提醒很重要**：0.5 或 1.5 倍时，30 秒整段时间轴未必正好走完整数圈，整段循环处可能跳回。路线自身闭合不代表整段视频必然无缝；报告会明确提示，不自动修改用户要求。若需要整段循环对齐，优先使用 1 或 2 倍。现有时间轴标记仍表示原路线关键点的归一化位置，不是每次错峰后的经过时刻。

## 可复用的数据关系层

`src/spatial-relations.js` 不依赖 App 或 Three.js。输入只包含 JSON 数据，求解返回新实体，不修改输入，不执行表达式、代码或插件。

支持四类基本关系：

| 关系 | 行为 | 当前集成 |
| --- | --- | --- |
| `anchor` | 将主体放到宿主的局部 `[side, y, forward]` 偏移，继承宿主 yaw | 两配方的招牌／暖窗组合实际使用该求解器 |
| `face` | 根据世界目标点计算主体的水平朝向 | 可复用编程 API／纯测；未开放任意自然语言朝向编辑 |
| `keep-out` | 检查旋转矩形的保守世界 AABB 在 XZ 平面是否侵入预留区域 | 商铺、民居与两座佛塔保留地块 |
| `distance` | 检查两实体的三维距离是否处于区间 | 可复用编程 API／纯测；未开放任意关系编辑器 |

示例（编程 API，不是 AI plan v1 工作包）：

```js
import { resolveSpatialRelations } from './src/spatial-relations.js';
const result = resolveSpatialRelations({
  version: 1,
  entities: [
    { id: 'shop', position: [10, 0, 20], yaw: Math.PI / 2 },
    { id: 'sign', position: [0, 0, 0], yaw: 0 },
  ],
  rules: [
    { type: 'anchor', subject: 'sign', host: 'shop', offset: [0, 4, 3] },
  ],
});
```

- 支持挂接链的依赖排序，不依赖声明顺序；拒绝循环、缺失／重复 ID、未知字段／类型、非有限数、原型字段和冲突写入。
- 预算：最多 300 实体、1000 关系。世界坐标 ±5000m，偏移 ±500m，平面半尺寸 0–500m；配方另有更小的 240 模型预算。
- 首版每实体最多一个姿态写入关系，不能同时给同一实体声明 `anchor` 与 `face`；约束冲突不会被静默猜测解决。
- `keep-out` 为保守平面 AABB，不是精确旋转多边形或 mesh 碰撞；`distance` 不会自动挪动对象满足区间。

`src/scene-relations.js` 将已有配方转换成关系图。生成前会核对挂接求解结果与实际对象位置，部件偏离挂接点、塔院侵入等硬错误阻止应用。**关系只在生成／预检时应用，不是编辑期持续约束**；不会在用户拖动宿主后擅自移动其它部件。

## 动态与空间检查

`src/scene-dynamics.js` 提供：

1. **几何路线检查**：不论倍率是否只走半圈，都检查完整路线；每条 241 个采样点，拒绝非法时间／坐标和超预算关键点。
2. **飞车扫掠检查**：对相邻采样点之间的线段做连续 slab 测试，不再只检查离散端点。使用按车长／宽计算的保守朝向半径，对塔楼 AABB 留出体积；仍是采样弦线，不是对完整样条或所有场景 mesh 的连续碰撞证明。
3. **三类步行带检查**：街侧人行道、古城岸上步行带、石拱桥宽度与拱面高度。发现走入河内、偏离人行道或穿过桥面会拒绝生成。
4. **车辆接近提示**：241 个同步时间样本上比较保守包围球，计算时使用实际倍率和相位。结果为提示，不等于精确相撞，也不自动重排交通。未实现行人互相避让或人车导航。
5. **时序检查**：显式时序只用于闭合路线，倍率 0.5–2、相位 `[0,1)`；非整数倍率提示整段循环接缝。

可选 `motion.schedule = {rate, phase}` 由 `src/motion-schedule.js` 统一映射到原路线进度，实际 App 播放／逐帧 step 使用它，不只是元数据。旧工程没有该字段时原样采样；原 `motion.speed` 仍是骨骼步态速度。异常导入的 schedule 在运行时安全回退，配方预检则拒绝。

## 保存与事务

- `generation.relations` 保存生成时关系图；`generation.checks` 保存重新预检得到的报告，而不是直接信任外部传来的结果。
- 生成模型的 `params.sceneRecipeNode` 映射关系图 ID，动态对象的 `params.sceneRouteRole` 记录路线类型。道路派生对象不冒充声明式关系节点。
- 时序、图与映射可保存恢复、随可移植工程归档，一步撤销重做保持；生成失败恢复原工程和历史的既有事务语义不变。
- 检查报告是**生成时快照**，不是修改后实时审计。编辑对象可能使它过期；本批没有新增「诊断当前编辑工程」或自动修复按钮。

## 未包含的能力

不是任意关系自然语言理解、任意场景整体优化、持续 rig、通用碰撞／导航系统或电影构图评分。没有把新关系协议直接暴露给 AI 网关；AI v1 的白名单不变。下一阶段若接入更复杂语义，仍须经过严格白名单、缺资源提示与候选确认，不能让模型输出任意可执行建模代码。本批没有付费外部 3D 服务调用。

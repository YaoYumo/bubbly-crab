# AI 搭景第二阶段：受控空间关系接入

2026-10-20。本轮把空间关系接进 AI 蓝图、工作包、同源网关、独立候选、差异清单、确认应用、撤销和审计。**不是任意自然语言理解或已验收的模型能力**：真实模型仍需在安装运行时的电脑上测试。旧关键词／配方入口不被替换；离线版可以手工提供同一份关系蓝图。

## 1. 直接试用，不需要模型

1. 打开 **Scene → AI 场景搭建 → 导入蓝图**，保持“添加”模式。
2. 展开 **空间关系蓝图（受控首版）**，点击 **填入离线空间关系示例**。
3. 示例只把 JSON 填入文本框，不联网、不修改工程；点击 **生成候选预览** 才进行检查。
4. 候选包含两个木箱：第二个在第一个东侧四米，模型 +Z 朝向第一个，距离恰好四米，平面留空至少一米。
5. 查看改动明细与空间关系说明，确认提示后才能应用。应用后可一步撤销。

示例使用当前工作包的范围、指纹和时长。若原场景中心已有锁定对象，候选仍可能因保护几何碰撞被拒绝；不是为了让示例通过而绕过保护。切到空白区域或另存后在空工程试用。它是两个木箱的规则示例，不是“AI 已理解复杂建筑布局”。

## 2. 可选协议扩展

仍为 `previz-ai-scene/1`，新增可选根字段 `relations`。没有该字段的已有蓝图、模板、工程和旧入口行为不变。较老程序会因未知字段拒绝新蓝图，应使用当前构建。

关系只能与显式 `operations` 配合，不能与 `recipe` 混用。仍至少需要一个操作，关系展开后总操作数不超过 180；规则数量为 1–128，协议版本为 1。完整结构见 [蓝图 JSON Schema](ai-scene.schema.json)，运行时还执行动态权限、资产与几何检查。

```json
{
  "relations": {
    "version": 1,
    "rules": [
      {"type":"offset","subject":"tea-house","reference":"bridge","delta":[10,0,0],"frame":"world"},
      {"type":"face","subject":"tea-house","target":"pagoda"},
      {"type":"distance","subject":"tea-house","target":"bridge","min":10,"max":10},
      {"type":"keep-out","subject":"tea-house","obstacle":"pagoda","margin":2}
    ]
  }
}
```

这是蓝图片段，不是独立可导入的完整蓝图；bridge、pagoda、tea-house 都必须是工作包或同一蓝图新增的**稳定对象 ID**，不是名字。网关把对象名视为不可信场景数据，不执行其中的指令。

| 关系 | 含义 |
| --- | --- |
| `offset` | 将 subject 的模型原点放到 reference 原点加 delta 的位置；`world` 是世界 XYZ，`local` 是参考物最终 Y 轴朝向下的 `[右,上,前]` |
| `face` | 让 subject 的模型 +Z 轴朝向 target 最终原点的 XZ 方向，只改 Y 轴朝向 |
| `distance` | 校验最终两个模型原点之间的三维欧氏距离，min／max 闭区间；不是自动挪动或沿路距离 |
| `keep-out` | 校验最终几何的 XZ 平面保守世界 AABB 留空，margin 按盒边扩展；忽略高度，不是精确网格碰撞或导航 |

约定 +X 东、+Z 南；米、Y 向上、弧度。同一对象可以有一条 offset 加一条 face；同类重复写入拒绝。位置／朝向分量分别解析依赖，因此互相面对可以成立；存在真正的依赖循环会拒绝，不猜测或迭代寻找解。

**“朝向佛塔”不是“门朝佛塔”**：本项目没有通用的语义门口、窗面、桥头或地块边界锚点。模型原点和 +Z 不保证等于实际门的位置与门朝向。十米偏移也不是两座建筑外墙间距。模型返回无法保证的门、脚接触等条件时不能宣称已经实现。

## 3. 解算和安全顺序

1. 校验根结构、规则字段、数量、有限数字、ID 和用户授权。
2. 在数据副本里模拟显式新增／移动／删除／重建，解析最终位置和朝向，再降低为原有显式操作。
3. 关系会覆盖其主体操作中的位置／朝向，新增对象的 placeholder `pos` 不作为最终位置检查。一个主体可以由关系补出明确 transform，但仍需要用户局部编辑授权、原位置在范围内且未锁定。
4. 用最终变换构建真实候选几何，再检查完整占地范围、保护对象、原有三角形预算和包围盒重叠。不能只检查模型原点。
5. 距离或留空要求不满足时拒绝候选；不会偷偷把它变成警告、默认造镇、自动移动或放松约束。
6. 候选差异清单列出规则、位置变化和编辑对象的 Y 朝向变化；关系行为边界作为需确认的提示。新关系写入保留在蓝图／应用审计中。
7. 原工程仍由既有事务守卫保护：准备不改源、源指纹变化拒绝、明确确认、失败恢复、一次撤销。应用时重新准备候选，不信任被篡改的候选文档。

原有蓝图 `placement:ground` 在关系计算前按初始位置采样一次高度。offset 的 Y 是相对参考物的世界高度，**不会在最终 XZ 再投影到地形**；关系主体最终改为 absolute 位置，坡面可能悬空，仍提示人工核查。local 只支持 Y 轴旋转，不支持倾斜宿主的完整三维变换。

## 4. 权限与支持边界

- 添加模式只能通过关系移动或旋转本轮新增对象，不能借关系绕过锁定或修改旧对象。
- 编辑模式可写的旧对象必须出现在 `editableIds`，未锁定／保护，原位置和最终占地均须在授权范围内。
- 锁定对象可以是只读参考物或约束对象，不会被解锁、重建或隐式移动。
- 首版仅支持现存静态库资产；不接受已删除对象、未知 ID、道路、植被 patch、无库 key 的导入模型或任意网格子节点作关系实体。
- 带活动走位或本蓝图计划设置走位的实体不参与关系，避免把播放中的世界轨迹错误当成静态布局。可写主体需未启用地形跟随，且仅有 Y 轴旋转。
- 关系是一次性布局，**不持久化为宿主／子件 rig**。应用后手工移动桥，茶馆不会自动跟随。这属于后续“编辑后诊断与组合件联动”，本轮未实现。
- 不新增自动避障、自动找空位、全局优化或复杂河口／人物接触求解；AABB 留空在旋转模型、悬空物体等场景可能过于保守。
- AI 服务现在能收到关系合同并返回关系蓝图，但没有运行真实模型语义推理。不能把协议 fixture 通过当成“中文复杂需求已可靠理解”。
